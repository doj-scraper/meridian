    24→## 1. Agent Lifecycle
    25→
    26→An agent goes through the following lifecycle from creation to execution:
    27→
    28→```
    29→┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
    30→│   CREATED   │────►│  CONFIGURED │────►│   RUNNING   │────►│  COMPLETED  │
    31→│             │     │             │     │             │     │             │
    32→│  Agent      │     │  Goal,      │     │  Executing  │     │  Goal       │
    33→│  exists in  │     │  tools,     │     │  steps in   │     │  achieved   │
    34→│  database   │     │  role set   │     │  loop       │     │  or failed  │
    35→└─────────────┘     └─────────────┘     └──────┬──────┘     └─────────────┘
    36→                                               │
    37→                                        ┌──────┴──────┐
    38→                                        │             │
    39→                                        ▼             ▼
    40→                                  ┌──────────┐  ┌──────────┐
    41→                                  │  STOPPED │  │  FAILED  │
    42→                                  │          │  │          │
    43→                                  │  User    │  │  Error   │
    44→                                  │  halted  │  │  occured │
    45→                                  └──────────┘  └──────────┘
    46→```
    47→
    48→### Creation Paths
    49→
    50→```
    51→Path 1: Template Quick-Create
    52→  User clicks template → createAgent() with preset config → agent appears in DB + canvas
    53→
    54→Path 2: AI Builder
    55→  User describes agent → buildAgent(userInput) → LLM generates config → save to DB
    56→
    57→Path 3: Manual Create
    58→  User clicks "New Agent" → createAgent() with minimal defaults → configure in inspector
    59→
    60→Path 4: Template Instantiation
    61→  POST /api/template/instantiate → creates agent from saved template with optional overrides
    62→```

    66→## 2. Agent Configuration
    67→
    68→### Complete Agent Schema
    69→
    70→```typescript
    71→interface AgentConfig {
    72→  // ── Identity ──
    73→  name: string;               // Display name (required)
    74→  goal: string;               // What the agent should accomplish (required)
    75→  personality: string;        // Behavioral modifier ("helpful and thorough assistant")
    76→
    77→  // ── Capabilities ──
    78→  tools: string[];            // Available tools: search, write, code, browser, finish
    79→  role: AgentRole;            // Role assignment (general, planner, researcher, executor, critic, reviewer)
    80→  model: string;              // LLM model: gemini-2.5-pro, gemini-2.5-flash, gpt-4o, etc.
    81→
    82→  // ── Execution ──
    83→  maxSteps: number;           // Maximum iteration steps (1-20, default 10)
    84→  autoRun: boolean;           // Whether to auto-execute on creation (default true)
    85→  outputFormat: string;       // Output format: text, json, markdown
    86→
    87→  // ── Orchestration ──
    88→  orchestrationMode: OrchestrationMode;  // single | sequential | group | hierarchical | parallel
    89→  maxConcurrency: number;     // Max parallel agents (for parallel mode, default 3)
    90→
    91→  // ── Memory ──
    92→  shortTermMemory: boolean;   // Enable session-scoped memory (default true)
    93→  longTermMemory: boolean;    // Enable persistent cross-run memory (default false)
    94→
    95→  // ── Reflection ──
    96→  reflectionEnabled: boolean;        // Enable critic-generator loop (default false)
    97→  reflectionMaxIter: number;         // Max reflection iterations (1-10, default 3)
    98→  reflectionCriteria: string;        // Approval criteria string (default "APPROVED")
    99→
   100→  // ── Canvas ──
   101→  graphData: {                 // React Flow graph position data
   102→    nodes: Node[];
   103→    edges: Edge[];
   104→  } | null;
   105→
   106→  // ── Team ──
   107→  teamId: string | null;      // Team membership (if part of a team)
   108→}
   109→```

   154→## 3. Execution Loop
   155→
   156→### Single Agent Run Loop
   157→
   158→```
   159→┌──────────────────────────────────────────────────────────┐
   160→│                    runAgent() Loop                        │
   161→│                                                          │
   162→│  1. Initialize run (create AgentRun in DB)               │
   163→│  2. Emit "status" event → { status: "running" }         │
   164→│  3. Loop (up to maxSteps):                               │
   165→│     │                                                    │
   166→│     ├── a. Check policy (policyEngine.check)             │
   167→│     │   ├── ALLOW → proceed                             │
   168→│     │   ├── BLOCK → emit "policy" event, stop           │
   169→│     │   ├── ASK_USER → create ApprovalRequest, wait      │
   170→│     │   └── SHADOW → proceed + log audit                │
   171→│     │                                                    │
   172→│     ├── b. Plan next action (planner.plan)               │
   173→│     │   ├── Send goal + context + tools to LLM           │
   174→│     │   ├── Parse LLM response → AgentAction             │
   175→│     │   └── Emit "plan" event                            │
   176→│     │                                                    │
   177→│     ├── c. Execute action (tools.execute)                │
   178→│     │   ├── Dispatch to tool handler                     │
   179→│     │   ├── Verify output (deterministic check)          │
   180→│     │   └── Emit "action" + "result" events             │
   181→│     │                                                    │
   182→│     ├── d. Record step in DB                             │
   183→│     │   └── Step { stepNum, tool, input, result, ... }   │
   184→│     │                                                    │
   185→│     ├── e. Update memory (memoryManager.set)             │
   186→│     │                                                    │
   187→│     ├── f. Check if done:                                │
   188→│     │   ├── Tool was "finish" → break loop               │
   189→│     │   └── Evaluator says goal met → break loop         │
   190→│     │                                                    │
   191→│     └── g. If not done → continue to next step           │
   192→│                                                          │
   193→│  4. Finalize run                                         │
   194→│     ├── Set AgentRun status → completed/failed/stopped   │
   195→│     ├── Compute metrics (tokens, latency, steps)         │
   196→│     └── Emit "done" event                                │
   197→│                                                          │
   198→│  5. Cleanup                                              │
   199→│     ├── Clear run memory (session tier)                  │
   200→│     └── Remove from active runs                          │
   201→└──────────────────────────────────────────────────────────┘
   202→```
   203→
   204→### Step Execution Detail
   205→
   206→```
   207→runStep(agent, runId, stepNum, history, memory)
   208→  │
   209→  ├── 1. Build context
   210→  │     ├── Agent goal + personality
   211→  │     ├── Role prompt modifier
   212→  │     ├── Tool descriptions
   213→  │     ├── Memory entries
   214→  │     └── Step history (previous actions + results)
   215→  │
   216→  ├── 2. Call planner.plan()
   217→  │     ├── Format prompt with context
   218→  │     ├── Call ZAI LLM SDK
   219→  │     └── Parse response → AgentAction
   220→  │         ├── Strategy 1: Direct JSON parse
   221→  │         ├── Strategy 2: Extract from ```json``` code block
   222→  │         ├── Strategy 3: Greedy JSON extraction (first { to last })
   223→  │         └── Strategy 4: Infer from tool mention in text
   224→  │
   225→  ├── 3. Emit "plan" event
   226→  │
   227→  ├── 4. Execute tool
   228→  │     ├── search → ZAI Web Search API
   229→  │     ├── write → Save to memory
   230→  │     ├── code → Execute with verification
   231→  │     ├── browser → ZAI Page Reader API
   232→  │     └── finish → Return result string
   233→  │
   234→  ├── 5. Verify output
   235→  │     ├── JSON validation (if applicable)
   236→  │     ├── Code compilation check (if code tool)
   237→  │     └── URL reachability (if browser tool)
   238→  │
   239→  ├── 6. Record Step in DB
   240→  │
   241→  └── 7. Return step result
   242→```
   243→
   244→### Event Types
   245→
   246→| Event Type | When Emitted | Data |
   247→|-----------|-------------|------|
   248→| `status` | Run starts/stops | `{ status: "running" \| "completed" \| "failed" }` |
   249→| `plan` | LLM generates next action | `{ step, tool, reasoning }` |
   250→| `action` | Tool execution begins | `{ step, tool, input }` |
   251→| `result` | Tool execution completes | `{ step, output, success }` |
   252→| `thinking` | LLM is processing (intermediate) | `{ message }` |
   253→| `error` | Error occurs | `{ message }` |
   254→| `done` | Run completes | `{ result, totalSteps, totalTokens }` |
   255→| `reflection` | Reflection iteration completes | `{ iteration, critique, approved }` |
   256→| `policy` | Policy blocks action | `{ tool, action, reason }` |
   257→| `handoff` | Agent passes output to next (sequential) | `{ fromAgent, toAgent }` |
   258→| `group_message` | Agent speaks in group chat | `{ agent, message }` |

   335→## 5. Role System
   336→
   337→### Role Architecture
   338→
   339→```
   340→┌──────────────────────────────────────────────────────────┐
   341→│                     Role System                           │
   342→│                                                          │
   343→│  Each role provides:                                     │
   344→│  ┌────────────────────────────────────────────────────┐  │
   345→│  │  Prompt Modifier                                    │  │
   346→│  │  Injected into LLM prompt to shape agent behavior  │  │
   347→│  │  e.g., "You are a planner. Break goals into        │  │
   348→│  │  subtasks and delegate to appropriate agents."     │  │
   349→│  └────────────────────────────────────────────────────┘  │
   350→│                                                          │
   351→│  ┌────────────────────────────────────────────────────┐  │
   352→│  │  Default Tools                                      │  │
   353→│  │  Pre-configured tool set for the role               │  │
   354→│  │  Planner: search, write                             │  │
   355→│  │  Executor: search, write, code                      │  │
   356→│  └────────────────────────────────────────────────────┘  │
   357→│                                                          │
   358→│  ┌────────────────────────────────────────────────────┐  │
   359→│  │  Permissions                                        │  │
   360→│  │  Access control: read, write, execute, approve,     │  │
   361→│  │  delegate                                            │  │
   362→│  └────────────────────────────────────────────────────┘  │
   363→│                                                          │
   364→│  ┌────────────────────────────────────────────────────┐  │
   365→│  │  Default Personality                                │  │
   366→│  │  Behavioral baseline for the role                   │  │
   367→│  │  Planner: "strategic and methodical"                │  │
   368→│  │  Critic: "analytical and constructively critical"   │  │
   369→│  └────────────────────────────────────────────────────┘  │
   370→└──────────────────────────────────────────────────────────┘
   371→```
   372→
   373→### Effective Personality Composition
   374→
   375→```
   376→Final Prompt = Base Personality + Role Prompt Modifier
   377→
   378→Example: Agent with personality="helpful assistant" and role="planner"
   379→
   380→  Base:       "You are a helpful assistant."
   381→  + Modifier: "You are a planner. Break goals into subtasks and
   382→               delegate to appropriate agents. Think step by step."
   383→  = Effective: "You are a helpful assistant. You are a planner.
   384→               Break goals into subtasks and delegate to appropriate
   385→               agents. Think step by step."
   386→```

   390→## 6. Orchestration Modes
   391→
   392→### Mode Overview
   393→
   394→```
   395→┌───────────────────────────────────────────────────────────────────┐
   396→│                    Orchestration Engine                            │
   397→│                                                                   │
   398→│  ┌─────────────┐  Simplest ←─────────────────────── Most Complex │
   399→│  │             │                                                  │
   400→│  │   SINGLE    │  One agent, one run, linear execution            │
   401→│  │             │  No coordination overhead                         │
   402→│  │      │      │                                                  │
   403→│  │      ▼      │                                                  │
   404→│  │ SEQUENTIAL  │  A→B→C handoff chain                             │
   405→│  │             │  Each agent receives previous agent's output      │
   406→│  │      │      │                                                  │
   407→│  │      ▼      │                                                  │
   408→│  │   GROUP     │  Shared scratchpad, LLM speaker selection        │
   409→│  │             │  Agents discuss until termination condition       │
   410→│  │      │      │                                                  │
   411→│  │      ▼      │                                                  │
   412→│  │HIERARCHICAL │  Manager → Workers → Synthesizer                 │
   413→│  │             │  Top-down task decomposition and delegation       │
   414→│  │      │      │                                                  │
   415→│  │      ▼      │                                                  │
   416→│  │  PARALLEL   │  Fan-out with semaphore concurrency control       │
   417→│  │             │  All agents run simultaneously, merge results     │
   418→│  └─────────────┘                                                  │
   419→└───────────────────────────────────────────────────────────────────┘
   420→```
   421→
   422→### Single Mode
   423→
   424→```
   425→User Goal → Agent → [Plan → Execute → Verify]* → Result
   426→```
   427→
   428→- One agent runs the full loop
   429→- No coordination overhead
   430→- Best for simple, well-defined tasks
   431→
   432→### Sequential Mode
   433→
   434→```
   435→┌────────┐     ┌────────┐     ┌────────┐
   436→│Agent A │────►│Agent B │────►│Agent C │
   437→│Research│     │Analyze │     │  Write │
   438→└────────┘     └────────┘     └────────┘
   439→     │              │              │
   440→     ▼              ▼              ▼
   441→  Output A      Output B      Final Output
   442→  = Input B     = Input C
   443→
   444→Events emitted: handoff (fromAgent, toAgent) between each step
   445→```
   446→
   447→- Agents run in series
   448→- Each agent's output becomes the next agent's input
   449→- Handoff events emitted between transitions
   450→
   451→### Group Chat Mode
   452→
   453→```
   454→┌───────────────────────────────────────────┐
   455→│              Shared Scratchpad             │
   456→│                                           │
   457→│  Agent A: "I found data on X..."          │
   458→│  Agent B: "Building on that, Y shows..."  │
   459→│  Agent A: "The key insight is Z..."       │
   460→│  Agent C: "I can verify this by..."       │
   461→│                                           │
   462→│  LLM Speaker Selection:                   │
   463→│  After each message, LLM chooses which    │
   464→│  agent speaks next based on context       │
   465→└───────────────────────────────────────────┘
   466→         │
   467→         ▼
   468→  Termination condition met → Synthesize final output
   469→
   470→Events emitted: group_message (agent, message)
   471→```
   472→
   473→- All agents share a conversation scratchpad
   474→- LLM decides which agent speaks next
   475→- Terminates on max_steps, text_mention, or max_messages
   476→
   477→### Hierarchical Mode
   478→
   479→```
   480→         ┌──────────┐
   481→         │ Manager  │
   482→         │(Planner) │
   483→         └────┬─────┘
   484→              │
   485→     ┌────────┼────────┐
   486→     │        │        │
   487→     ▼        ▼        ▼
   488→┌────────┐┌────────┐┌────────┐
   489→│Worker 1││Worker 2││Worker 3│
   490→│Research││Execute ││Review  │
   491→└────┬───┘└────┬───┘└────┬───┘
   492→     │         │         │
   493→     └─────────┼─────────┘
   494→               │
   495→               ▼
   496→         ┌──────────────┐
   497→         │ Synthesizer  │
   498→         │ (Manager)    │
   499→         └──────────────┘
   500→               │
   501→               ▼
   502→          Final Output
   503→```
   504→
   505→- Manager decomposes goal into subtasks
   506→- Delegates subtasks to worker agents
   507→- Workers execute independently
   508→- Manager synthesizes all worker outputs
   509→
   510→### Parallel Mode
   511→
   512→```
   513→           ┌──────────┐
   514→           │  Fan-out  │
   515→           └────┬─────┘
   516→                │
   517→      ┌─────────┼─────────┐
   518→      │         │         │
   519→      ▼         ▼         ▼
   520→┌──────────┐┌──────────┐┌──────────┐
   521→│ Agent A  ││ Agent B  ││ Agent C  │
   522→│          ││          ││          │
   523→│ Semaphore││ Semaphore││ Semaphore│
   524→│  Slot 1  ││  Slot 2  ││  Slot 3  │
   525→└────┬─────┘└────┬─────┘└────┬─────┘
   526→     │           │           │
   527→     └───────────┼───────────┘
   528→                 │
   529→                 ▼
   530→          ┌────────────┐
   531→          │  Merge     │
   532→          │  Results   │
   533→          └────────────┘
   534→```
   535→
   536→- All agents run simultaneously
   537→- Semaphore controls max concurrency (configurable, default 3)
   538→- Results merged in agent order after all complete
   539→- Best for independent research tasks

   557→## 7. Memory System
   558→
   559→### 3-Tier Architecture
   560→
   561→```
   562→┌─────────────────────────────────────────────────────────┐
   563→│                   MemoryManager                          │
   564→│                                                          │
   565→│  ┌────────────────────────────────────────────────────┐ │
   566→│  │  TIER 1: SESSION (In-Memory)                       │ │
   567→│  │                                                    │ │
   568→│  │  • Stored in Map<runId, Map<key, entry>>           │ │
   569→│  │  • Scoped to a single run                          │ │
   570→│  │  • Auto-expires after 24 hours                     │ │
   571→│  │  • Fastest read/write                              │ │
   572→│  │  • Cleared on clearSession() or run end            │ │
   573→│  │  • Use case: temporary working data, context       │ │
   574→│  └────────────────────────────────────────────────────┘ │
   575→│                                                          │
   576→│  ┌────────────────────────────────────────────────────┐ │
   577→│  │  TIER 2: PERSISTENT (Database)                     │ │
   578→│  │                                                    │ │
   579→│  │  • Stored in AgentMemory table                     │ │
   580→│  │  • Unique key: (agentId, key, tier)                │ │
   581→│  │  • Upsert semantics (update or create)             │ │
   582→│  │  • Survives across runs                            │ │
   583→│  │  • Use case: learned facts, user preferences       │ │
   584→│  └────────────────────────────────────────────────────┘ │
   585→│                                                          │
   586→│  ┌────────────────────────────────────────────────────┐ │
   587→│  │  TIER 3: ARTIFACT (Database)                       │ │
   588→│  │                                                    │ │
   589→│  │  • Stored in Artifact table                        │ │
   590→│  │  • Unique key: (agentId, name)                     │ │
   591→│  │  • Rich metadata (type, runId, custom metadata)    │ │
   592→│  │  • Large content blobs (code, documents, data)     │ │
   593→│  │  • Use case: generated reports, code files, data   │ │
   594→│  └────────────────────────────────────────────────────┘ │
   595→│                                                          │
   596→│  API:                                                    │
   597→│    get(agentId, key, tier?) → value                      │
   598→│    set(agentId, key, value, tier, runId?) → void         │
   599→│    delete(agentId, key, tier) → void                     │
   600→│    list(agentId, tier?) → MemoryEntry[]                  │
   601→│    clearSession(runId) → void                            │
   602→│    saveArtifact(agentId, name, type, content, meta?) → a │
   603→│    listArtifacts(agentId) → Artifact[]                   │
   604→│    getArtifact(agentId, name) → Artifact                 │
   605→└─────────────────────────────────────────────────────────┘
   606→```

   609→
   610→```

   612→  │

   615→  │   ├── Persistent: cross-run learned facts
   616→  │   └── Artifact: reference documents
   617→  │

   620→  └── Write: Save new insights

   628→## 8. Policy & Governance
   629→
   630→### Policy Engine Architecture
   631→
   632→```
   633→┌─────────────────────────────────────────────────────────┐
   634→│                    PolicyEngine                          │
   635→│                                                          │
   636→│  Input: tool, role, riskLevel, agentId                  │
   637→│                                                          │
   638→│  1. Load all enabled policies (sorted by priority DESC) │
   639→│                                                          │
   640→│  2. Evaluate each policy:                               │
   641→│     ┌─────────────────────────────────────┐             │
   642→│     │  Condition Match:                    │             │
   643→│     │  • tool: ["execute_code", ...]       │             │
   644→│     │  • role: ["executor", ...]           │             │
   645→│     │  • riskLevel: ["high", "critical"]   │             │
   646→│     │  • agentId: ["specific-agent-id"]    │             │
   647→│     │                                      │             │
   648→│     │  If ALL condition fields match →     │             │
   649→│     │    Apply this policy's action         │             │
   650→│     └─────────────────────────────────────┘             │
   651→│                                                          │
   652→│  3. First matching policy wins (priority order)         │
   653→│                                                          │
   654→│  4. Return PolicyCheckResult:                           │
   655→│     ├── action: allow | block | ask_user | shadow       │
   656→│     ├── matchedPolicy: PolicyRule | null                │
   657→│     └── reason: string                                  │
   658→│                                                          │
   659→│  5. Log to AuditLog (always, regardless of action)      │
   660→└─────────────────────────────────────────────────────────┘
   661→```
   662→
   663→### Policy Actions
   664→
   665→| Action | Behavior | UI Impact |
   666→|--------|----------|-----------|
   667→| `allow` | Execute tool normally | No interruption |
   668→| `block` | Prevent execution, return error | Red error event in stream |
   669→| `ask_user` | Pause execution, create ApprovalRequest | ApprovalModal appears |
   670→| `shadow` | Execute tool + log audit, no interruption | No visible interruption |
   671→
   672→### Default Policies (Pre-seeded)
   673→
   674→| Priority | Name | Condition | Action |
   675→|----------|------|-----------|--------|
   676→| 100 | Block critical risk | riskLevel = critical | block |
   677→| 90 | Require approval for code execution | tool = execute_code | ask_user |
   678→| 80 | Block all for reviewer role | role = reviewer | block (execute) |
   679→| 70 | Allow read operations | tool = search \| browse_url \| read_memory | allow |
   680→| 60 | Allow general role | role = general | allow |
   681→
   682→### Approval Workflow
   683→
   684→```
   685→┌──────────┐     ┌───────────────┐     ┌──────────────┐
   686→│  Agent   │────►│ ApprovalReq   │────►│  Human User  │
   687→│  Wants   │     │  (pending)    │     │  Sees Modal  │
   688→│  to Act  │     │  in DB        │     │              │
   689→└──────────┘     └───────────────┘     └──────┬───────┘
   690→                                               │
   691→                                        ┌──────┴───────┐
   692→                                        │              │
   693→                                     Approved        Denied
   694→                                        │              │
   695→                                        ▼              ▼
   696→                                   Execute tool    Emit error
   697→                                   + update        + update
   698→                                   approval        approval
   699→                                   status          status
   700→```

   704→## 9. Reflection Loop
   705→
   706→### Critic-Generator Pattern
   707→
   708→```
   709→┌──────────────────────────────────────────────────────────┐
   710→│                  Reflection Loop                          │
   711→│                                                          │
   712→│  Initial Output (from agent execution)                   │
   713→│       │                                                  │
   714→│       ▼                                                  │
   715→│  ┌──────────────┐                                        │
   716→│  │  ITERATION 1 │                                        │
   717→│  │              │                                        │
   718→│  │  Generator:  │  "Here is the analysis..."            │
   719→│  │  produces    │                                        │
   720→│  │  output      │                                        │
   721→│  │              │                                        │
   722→│  │  Critic:     │  "The analysis lacks depth on X.      │
   723→│  │  evaluates   │   Please revise with more detail."    │
   724→│  │              │                                        │
   725→│  │  Approved?   │  NO → Continue                        │
   726→│  └──────────────┘                                        │
   727→│       │                                                  │
   728→│       ▼                                                  │
   729→│  ┌──────────────┐                                        │
   730→│  │  ITERATION 2 │                                        │
   731→│  │              │                                        │
   732→│  │  Generator:  │  "Revised analysis with X detail..."  │
   733→│  │  revises     │                                        │
   734→│  │  based on    │                                        │
   735→│  │  critique    │                                        │
   736→│  │              │                                        │
   737→│  │  Critic:     │  "APPROVED"                            │
   738→│  │  evaluates   │                                        │
   739→│  │              │                                        │
   740→│  │  Approved?   │  YES → Break                           │
   741→│  └──────────────┘                                        │
   742→│       │                                                  │
   743→│       ▼                                                  │
   744→│  Return final output                                     │
   745→│                                                          │
   746→│  Safety: Max iterations (default 3) prevents infinite    │
   747→│  loops. If max reached without approval, return latest.  │
   748→└──────────────────────────────────────────────────────────┘
   749→```
   750→
   751→### Reflection Configuration
   752→
   753→```typescript
   754→interface ReflectionConfig {
   755→  enabled: boolean;            // Master toggle
   756→  maxIterations: number;       // Max critic-generator cycles (1-10)
   757→  criteria: string;            // Approval criteria string (default "APPROVED")
   758→}
   759→```
   760→
   761→### Reflection Persistence
   762→
   763→Each iteration is stored in the `ReflectionIteration` database table:
   764→
   765→| Field | Type | Description |
   766→|-------|------|-------------|
   767→| `id` | cuid | Primary key |
   768→| `runId` | string | FK to AgentRun |
   769→| `iteration` | number | Cycle number (1, 2, 3...) |
   770→| `output` | string | Generator's output |
   771→| `critique` | string | Critic's evaluation |
   772→| `approved` | boolean | Whether critic approved |

   875→
   876→### JSON Extraction Strategies
   877→
   878→When the LLM returns a response, the planner tries 4 strategies to extract valid JSON:
   879→
   880→```
   881→Strategy 1: Direct Parse
   882→  → Try JSON.parse(entire response)
   883→  → Success rate: Low (LLM often adds prose)
   884→
   885→Strategy 2: Code Block Extraction
   886→  → Find ```json ... ``` in response
   887→  → Parse the content between backticks
   888→  → Success rate: Medium
   889→
   890→Strategy 3: Greedy JSON Extraction
   891→  → Find first { and last }
   892→  → Parse substring
   893→  → Success rate: High (catches most cases)
   894→
   895→Strategy 4: Tool Mention Inference
   896→  → If no JSON found, scan text for tool names
   897→  → Create a simple action based on mention
   898→  → Success rate: Fallback only
   899→```
