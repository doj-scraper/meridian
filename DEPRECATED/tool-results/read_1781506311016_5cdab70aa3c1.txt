    30→## 1. Executive Summary
    31→
    32→Agent Studio OS V1 is a **functional prototype** — it demonstrates the concept of a visual AI agent builder with canvas-based editing, SSE streaming, and an AI Builder wizard. However, it has **critical production gaps** that prevent enterprise deployment:
    33→
    34→- **3 critical memory leaks** that will crash any long-running server
    35→- **All tools are simulated** — the agent loop is LLM → mock → LLM
    36→- **Zero authentication** — no user ownership, no access control
    37→- **Fragile LLM output parsing** — non-greedy regex on nested JSON
    38→- **No concurrency control** — unlimited simultaneous agent runs
    39→- **SQLite with no indexes** — will degrade under multi-user load
    40→- **No canvas persistence** — user layouts lost on refresh
    41→- **No policy/approval system** — agents can execute any action unchecked
    42→
    43→V2 transforms this into an **enterprise-grade Agent Runtime OS** through 4 phases:
    44→
    45→| Phase | Focus | Timeline | Enterprise Value |
    46→|-------|-------|----------|------------------|
    47→| **P0** | Critical fixes + real tools | Week 1 | System won't crash or leak memory |
    48→| **P1** | Multi-agent orchestration | Weeks 2-4 | Core differentiator — collaborative agents |
    49→| **P2** | Memory, verification, tools | Weeks 5-6 | Reliability — agents produce verified outputs |
    50→| **P3** | Governance, observability | Weeks 7-9 | Trust — auditable, controllable, observable |
    51→| **P4** | Advanced features & scale | Weeks 10-12 | Growth — parallel execution, task graphs, triggers |
    52→
    53→**The transformation:** From a single-agent task-orchestration UI → Multi-agent autonomous runtime OS with enterprise-grade safety, observability, and reliability.

    82→### 2.2 Architecture Gaps (Prototype vs Enterprise)
    83→
    84→| Dimension | V1 (Prototype) | V2 (Enterprise) | Gap |
    85→|-----------|----------------|-----------------|-----|
    86→| **Execution** | Single agent, sequential only | Multi-agent: sequential, group, hierarchical, parallel | 🔴 Fundamental |
    87→| **Quality** | Single-pass, no self-review | Reflection loops with generator→critic iteration | 🔴 Fundamental |
    88→| **Composition** | All agents identical | Role-based: planner, researcher, executor, critic, reviewer | 🔴 Fundamental |
    89→| **Memory** | In-memory only, resets on restart | 3-tier: session, persistent DB, versioned artifacts | 🔴 Data loss |
    90→| **Tools** | All simulated, no verification | Real implementations with deterministic validators | 🔴 Non-functional |
    91→| **Safety** | Kill switch only | Policy engine, approval gates, audit trail | 🔴 Uncontrolled |
    92→| **Observability** | Basic SSE events | Timeline, metrics, token tracking, failure analysis | 🟡 Blind spots |
    93→| **Auth** | None | User ownership, RBAC, scoped access | 🔴 No access control |
    94→| **Database** | SQLite, no indexes, no enums | Indexed, enum-constrained, migration-ready | 🟡 Performance |
    95→| **Error Handling** | Try/catch → console.error | Structured errors, retry, graceful degradation | 🟡 Fragile |
    96→| **Deployment** | Single process, no scaling | Containerized, horizontal scaling ready | 🟡 Single point of failure |

    98→### 2.3 What the Research Documents Tell Us
    99→
   100→The four uploaded documents provide critical design guidance:
   101→
   102→**From agenticNotebooklm.md (AutoGen Research):**
   103→- Sequential workflow = publish-subscribe topics, each agent subscribes to its own topic
   104→- Group chat = shared scratchpad + Group Chat Manager with `RequestToSpeak`
   105→- Speaker selection: prefer rule-based over LLM-based when order is obvious (saves tokens/latency)
   106→- Termination conditions: `TextMentionTermination("APPROVE")` + `MaxMessageTermination` combined with `|` operator
   107→- Round-robin for fixed order, SelectorGroupChat for dynamic delegation
   108→
   109→**From agentsNotebooklm.md (Agent Architecture Research):**
   110→- **The "combo" effect:** Weaker delegative planner + strong solver > single dominant model
   111→- **Security risks unique to multi-agent:** Confused Deputy attacks, cross-agent privilege escalation, collusion
   112→- **SEAgent's MAC model:** Decision Engine checks every tool call against Policy DB → Block/Deny, User Prompt/Ask, or Shadow Mode
   113→- **AgentCgroup:** AI agents have 15.4× peak-to-average memory ratio, burst-silence pattern, 56-74% latency from OS execution
   114→- **Soft limits > hard kills:** OOM kills destroy non-recoverable LLM context; throttling preserves state
   115→- **Understand-Modify-Verify lifecycle:** Early phase = lightweight reads, mid-late = heavy bash calls
   116→
   117→**From AGENTIC_OS_V2_PLAN.md (V2 Roadmap):**

   241→### 3.3 Key Architecture Decisions
   242→
   243→| Decision | Choice | Rationale |
   244→|----------|--------|-----------|
   245→| **Orchestration pattern** | Strategy pattern with mode routing | Clean separation, testable strategies, easy to add modes |
   246→| **Memory architecture** | 3-tier with DB persistence | Survives restarts, queryable, multi-instance safe |
   247→| **Policy enforcement** | Pre-execution hook in agent loop | Catches actions before they happen, not after |
   248→| **LLM output parsing** | Zod schema validation | Replaces fragile regex, validates at runtime, typed output |
   249→| **Event system** | Typed SSE with sequence numbers | Solves ordering, deduplication, and multi-agent event correlation |
   250→| **Concurrency control** | Semaphore + run queue | Prevents resource exhaustion, configurable limits |
   251→| **Canvas state** | Server-authoritative (graphData) | Survives refresh, shareable, restorable |

   317→### 4.3 — LLM Output Parsing Fix
   318→
   319→**C05: Replace regex with structured extraction**
   320→```typescript
   321→// planner.ts — Replace fragile regex with zod validation
   322→import { z } from 'zod';
   323→
   324→const ActionSchema = z.object({
   325→  tool: z.enum(['search', 'write', 'code', 'browser', 'finish']),
   326→  input: z.string()
   327→});
   328→
   329→function extractAction(content: string): AgentAction {
   330→  // Try multiple extraction strategies
   331→  // 1. Direct JSON parse
   332→  try {
   333→    const parsed = JSON.parse(content);
   334→    return ActionSchema.parse(parsed);
   335→  } catch {}
   336→  
   337→  // 2. Extract from markdown code block
   338→  const codeBlockMatch = content.match(/```json\s*([\s\S]*?)```/);
   339→  if (codeBlockMatch) {
   340→    try {
   341→      const parsed = JSON.parse(codeBlockMatch[1]);
   342→      return ActionSchema.parse(parsed);
   343→    } catch {}
   344→  }
   345→  
   346→  // 3. Find last JSON object (greedy, handles nested)
   347→  const jsonMatch = content.match(/\{[\s\S]*\}/);
   348→  if (jsonMatch) {
   349→    try {
   350→      const parsed = JSON.parse(jsonMatch[0]);
   351→      return ActionSchema.parse(parsed);
   352→    } catch {}
   353→  }
   354→  
   355→  // 4. Fallback with retry prompt
   356→  return { tool: 'finish', input: `Could not parse action from LLM response. Original: ${content.substring(0, 200)}` };
   357→}
   358→```

   403→### 4.5 — Concurrency Control
   404→
   405→**C07: Add run queue with limits**
   406→
   407→```typescript
   408→// agent.ts — Add concurrency limiting
   409→const MAX_CONCURRENT_RUNS = 5;
   410→const activeRunCount = { value: 0 };
   411→const runQueue: Array<{ runId: string; config: AgentConfig; resolve: Function; reject: Function }> = [];
   412→
   413→export async function runAgent(runId: string, config: AgentConfig): Promise<void> {
   414→  if (activeRunCount.value >= MAX_CONCURRENT_RUNS) {
   415→    return new Promise((resolve, reject) => {
   416→      runQueue.push({ runId, config, resolve, reject });
   417→    });
   418→  }
   419→  
   420→  activeRunCount.value++;
   421→  try {
   422→    await executeRun(runId, config);
   423→  } finally {
   424→    activeRunCount.value--;
   425→    processQueue();
   426→  }
   427→}
   428→
   429→function processQueue() {
   430→  while (activeRunCount.value < MAX_CONCURRENT_RUNS && runQueue.length > 0) {
   431→    const { runId, config, resolve, reject } = runQueue.shift()!;
   432→    activeRunCount.value++;
   433→    executeRun(runId, config)
   434→      .then(resolve)

   437→  }
   438→}

   605→### 5.1 — Orchestration Mode Engine
   606→
   607→**Research basis (agenticNotebooklm.md):** AutoGen defines 3 core patterns — Sequential Pipeline, Group Chat, Hierarchical Chat. We add Parallel as a 4th.
   608→
   609→```typescript
   610→// NEW FILE: src/lib/agent/orchestrator.ts
   611→import { EventEmitter } from 'events';
   612→
   613→export type OrchestrationMode = 'single' | 'sequential' | 'group' | 'hierarchical' | 'parallel';
   614→
   615→export interface TeamConfig {
   616→  id: string;
   617→  name: string;
   618→  mode: OrchestrationMode;
   619→  agents: AgentConfig[];
   620→  termination: TerminationCondition;
   621→  maxConcurrency?: number;
   622→  sharedContext?: boolean;
   623→}
   624→
   625→export type TerminationCondition =
   626→  | { type: 'max_steps'; value: number }
   627→  | { type: 'text_mention'; text: string }
   628→  | { type: 'max_messages'; value: number }
   629→  | { type: 'composite'; conditions: TerminationCondition[]; operator: 'and' | 'or' };
   630→
   631→export class AgentOrchestrator extends EventEmitter {
   632→  private activeOrchestrations = new Map<string, AbortController>();
   633→
   634→  async run(team: TeamConfig, input: string): Promise<string> {
   635→    const controller = new AbortController();
   636→    this.activeOrchestrations.set(team.id, controller);
   637→
   638→    try {
   639→      switch (team.mode) {
   640→        case 'single':     return await this.runSingle(team, input, controller.signal);
   641→        case 'sequential': return await this.runSequential(team, input, controller.signal);
   642→        case 'group':      return await this.runGroup(team, input, controller.signal);
   643→        case 'hierarchical': return await this.runHierarchical(team, input, controller.signal);
   644→        case 'parallel':   return await this.runParallel(team, input, controller.signal);
   645→      }
   646→    } finally {
   647→      this.activeOrchestrations.delete(team.id);
   648→    }
   649→  }
   650→
   651→  stop(teamId: string): void {
   652→    this.activeOrchestrations.get(teamId)?.abort();
   653→  }
   654→
   655→  private async runSingle(team: TeamConfig, input: string, signal: AbortSignal): Promise<string> {
   656→    // Backward-compatible: run first agent only
   657→    return executeAgent(team.agents[0], input, { signal, emitter: this });
   658→  }
   659→
   660→  private async runSequential(team: TeamConfig, input: string, signal: AbortSignal): Promise<string> {
   661→    // Pipeline: A → B → C, output handoff between stages
   662→    let currentInput = input;
   663→    for (const agent of team.agents) {
   664→      if (signal.aborted) throw new Error('Orchestration aborted');
   665→      const result = await executeAgent(agent, currentInput, { signal, emitter: this });
   666→      this.emit('handoff', { from: agent.name, to: team.agents[team.agents.indexOf(agent) + 1]?.name, data: result.substring(0, 200) });
   667→      currentInput = result;
   668→    }
   669→    return currentInput;
   670→  }
   671→
   672→  private async runGroup(team: TeamConfig, input: string, signal: AbortSignal): Promise<string> {
   673→    // Shared scratchpad with turn-taking manager
   674→    const history: GroupChatMessage[] = [{ role: 'user', content: input, source: 'user' }];
   675→    let messageCount = 0;
   676→
   677→    while (!this.checkTermination(history, team.termination, messageCount)) {
   678→      if (signal.aborted) throw new Error('Orchestration aborted');
   679→      
   680→      const nextSpeaker = await this.selectNextSpeaker(team, history);
   681→      const response = await executeAgentTurn(nextSpeaker, history, { signal, emitter: this });
   682→      
   683→      history.push({ role: 'assistant', content: response, source: nextSpeaker.name });
   684→      messageCount++;
   685→      
   686→      this.emit('group_message', { speaker: nextSpeaker.name, message: response.substring(0, 200) });
   687→    }
   688→
   689→    return history[history.length - 1]?.content ?? '';
   690→  }
   691→
   692→  private async runHierarchical(team: TeamConfig, input: string, signal: AbortSignal): Promise<string> {
   693→    // Manager delegates to workers, collects results
   694→    const manager = team.agents.find(a => a.role === 'planner') ?? team.agents[0];
   695→    const workers = team.agents.filter(a => a.role !== 'planner');
   696→
   697→    // Manager decomposes goal
   698→    const plan = await executeAgent(manager, `Decompose this goal into sub-tasks: ${input}`, { signal, emitter: this });
   699→    
   700→    // Workers execute sub-tasks
   701→    const workerResults: Record<string, string> = {};
   702→    for (const worker of workers) {
   703→      if (signal.aborted) throw new Error('Orchestration aborted');
   704→      const task = await this.assignTask(manager, worker, plan, workerResults);
   705→      const result = await executeAgent(worker, task, { signal, emitter: this });
   706→      workerResults[worker.name] = result;
   707→    }
   708→
   709→    // Manager synthesizes
   710→    return await executeAgent(manager, `Synthesize final answer from worker results:\n${JSON.stringify(workerResults)}`, { signal, emitter: this });
   711→  }
   712→
   713→  private async runParallel(team: TeamConfig, input: string, signal: AbortSignal): Promise<string> {
   714→    // Fan-out with concurrency limit
   715→    const maxConcurrency = team.maxConcurrency ?? 3;
   716→    const results: Record<string, string> = {};
   717→    const semaphore = new Semaphore(maxConcurrency);
   718→
   719→    await Promise.allSettled(
   720→      team.agents.map(async (agent) => {
   721→        await semaphore.acquire();
   722→        try {
   723→          if (signal.aborted) return;
   724→          const result = await executeAgent(agent, input, { signal, emitter: this });
   725→          results[agent.name] = result;
   726→        } finally {
   727→          semaphore.release();
   728→        }
   729→      })
   730→    );
   731→
   732→    // Merge results
   733→    return Object.entries(results).map(([name, result]) => `## ${name}\n${result}`).join('\n\n');
   734→  }
   735→
   736→  // ... helper methods
   737→}
   738→
   739→// Simple semaphore for concurrency control
   740→class Semaphore {
   741→  private queue: (() => void)[] = [];
   742→  private running = 0;
   743→  constructor(private max: number) {}
   744→  
   745→  async acquire(): Promise<void> {
   746→    if (this.running < this.max) {
   747→      this.running++;
   748→      return;
   749→    }
   750→    return new Promise<void>(resolve => this.queue.push(resolve));
   751→  }
   752→  
   753→  release(): void {
   754→    this.running--;
   755→    const next = this.queue.shift();
   756→    if (next) { this.running++; next(); }
   757→  }
   758→}
   759→```

   761→### 5.2 — Reflection Loop System
   762→
   763→**Research basis:** The Evaluator-Optimizer pattern from agenticNotebooklm.md. GPT-3.5 jumps from 48.1% → 95.1% on coding benchmarks with agentic refinement. Key practices: cap iterations, use explicit approval criteria, optionally insert human as evaluator.
   764→
   765→```typescript
   766→// NEW FILE: src/lib/agent/reflection.ts
   767→import { getZAI } from './zai-client';
   768→
   769→export interface ReflectionConfig {
   770→  enabled: boolean;
   771→  maxIterations: number;      // Default: 3
   772→  criticPrompt: string;        // Custom critic system prompt
   773→  approvalKeyword: string;     // Default: "APPROVED"
   774→  requireHumanApproval: boolean; // For high-stakes outputs
   775→}
   776→
   777→export interface ReflectionIteration {
   778→  iteration: number;
   779→  output: string;
   780→  critique: string;
   781→  approved: boolean;
   782→  timestamp: Date;
   783→}
   784→
   785→export async function runReflectionLoop(
   786→  initialOutput: string,
   787→  goal: string,
   788→  config: ReflectionConfig,
   789→  emitter: EventEmitter
   790→): Promise<{ output: string; iterations: ReflectionIteration[]; approved: boolean }> {
   791→  const iterations: ReflectionIteration[] = [];
   792→  let currentOutput = initialOutput;
   793→  let approved = false;
   794→  let iteration = 0;
   795→
   796→  while (iteration < config.maxIterations && !approved) {
   797→    // Critic evaluates
   798→    emitter.emit('reflection', { type: 'critique_start', iteration });
   799→    const critique = await critiqueOutput(currentOutput, goal, config);
   800→    emitter.emit('reflection', { type: 'critique_done', iteration, critique: critique.substring(0, 200) });
   801→
   802→    approved = critique.toUpperCase().includes(config.approvalKeyword);
   803→    
   804→    iterations.push({
   805→      iteration,
   806→      output: currentOutput,
   807→      critique,
   808→      approved,
   809→      timestamp: new Date()
   810→    });
   811→
   812→    if (!approved && iteration < config.maxIterations - 1) {
   813→      // Generator revises
   814→      emitter.emit('reflection', { type: 'revision_start', iteration });
   815→      currentOutput = await reviseOutput(currentOutput, critique, goal, config);
   816→      emitter.emit('reflection', { type: 'revision_done', iteration });
   817→    }
   818→
   819→    iteration++;
   820→  }
   821→
   822→  return { output: currentOutput, iterations, approved };
   823→}
   824→
   825→async function critiqueOutput(output: string, goal: string, config: ReflectionConfig): Promise<string> {
   826→  const zai = await getZAI();
   827→  const response = await zai.chat({
   828→    messages: [
   829→      { role: 'system', content: config.criticPrompt || `You are a quality critic. Evaluate the output against the goal. If satisfactory, respond with "${config.approvalKeyword}". Otherwise, provide specific, actionable feedback for improvement.` },
   830→      { role: 'user', content: `Goal: ${goal}\n\nOutput to evaluate:\n${output}` }
   831→    ]
   832→  });
   833→  return response.choices[0]?.message?.content ?? '';
   834→}
   835→
   836→async function reviseOutput(output: string, critique: string, goal: string, config: ReflectionConfig): Promise<string> {
   837→  const zai = await getZAI();
   838→  const response = await zai.chat({
   839→    messages: [
   840→      { role: 'system', content: 'You are an expert generator. Revise the output based on the critique provided. Address every point of feedback.' },
   841→      { role: 'user', content: `Goal: ${goal}\n\nCurrent output:\n${output}\n\nCritique:\n${critique}\n\nPlease provide a revised output that addresses all feedback.` }
   842→    ]
   843→  });
   844→  return response.choices[0]?.message?.content ?? output;
   845→}

  1008→```typescript

  1092→### 6.2 — Tool Registry & Verification
  1093→
  1094→**Research basis:** RLVR (Reinforcement Learning with Verifiable Rewards) outperforms Process Reward Models because deterministic checks (JSON parsing, code compilation) are immune to reward hacking. We use this principle for tool verification — deterministic validators over LLM judges.
  1095→
  1096→```typescript
  1097→// NEW FILE: src/lib/agent/tool-registry.ts
  1098→import { z } from 'zod';
  1099→
  1100→export interface ToolDefinition {
  1101→  id: string;
  1102→  name: string;
  1103→  description: string;
  1104→  category: 'search' | 'write' | 'code' | 'browser' | 'memory' | 'api' | 'custom';
  1105→  riskLevel: 'low' | 'medium' | 'high';
  1106→  parameters: z.ZodSchema;
  1107→  validator?: ToolValidator;
  1108→  executor: (params: any) => Promise<string>;
  1109→}
  1110→
  1111→export interface ToolValidator {
  1112→  type: 'json_schema' | 'code_compiles' | 'url_reachable' | 'regex_match' | 'custom';
  1113→  config: Record<string, any>;
  1114→}
  1115→
  1116→export interface VerificationResult {
  1117→  status: 'verified' | 'failed' | 'needs_review';
  1118→  message: string;
  1119→  details?: any;
  1120→}
  1121→
  1122→class ToolRegistry {
  1123→  private tools = new Map<string, ToolDefinition>();
  1124→
  1125→  register(tool: ToolDefinition): void {
  1126→    this.tools.set(tool.id, tool);
  1127→  }
  1128→
  1129→  get(id: string): ToolDefinition | undefined {
  1130→    return this.tools.get(id);
  1131→  }
  1132→
  1133→  list(category?: string): ToolDefinition[] {
  1134→    const all = Array.from(this.tools.values());
  1135→    return category ? all.filter(t => t.category === category) : all;
  1136→  }
  1137→
  1138→  async executeWithVerification(
  1139→    toolId: string,
  1140→    params: any,
  1141→    maxRetries: number = 1
  1142→  ): Promise<{ result: string; verification: VerificationResult }> {
  1143→    const tool = this.tools.get(toolId);
  1144→    if (!tool) throw new Error(`Unknown tool: ${toolId}`);
  1145→
  1146→    // Validate params
  1147→    const validated = tool.parameters.parse(params);
  1148→
  1149→    let result: string;
  1150→    let attempts = 0;
  1151→
  1152→    do {
  1153→      result = await tool.executor(validated);
  1154→      
  1155→      if (!tool.validator) {
  1156→        return { result, verification: { status: 'needs_review', message: 'No validator configured' } };
  1157→      }
  1158→
  1159→      const verification = await this.verify(result, tool.validator);
  1160→      if (verification.status === 'verified') {
  1161→        return { result, verification };
  1162→      }
  1163→
  1164→      attempts++;
  1165→    } while (attempts < maxRetries);
  1166→
  1167→    return { result, verification: { status: 'failed', message: `Failed after ${maxRetries} attempts` } };
  1168→  }
  1169→
  1170→  private async verify(output: string, validator: ToolValidator): Promise<VerificationResult> {
  1171→    switch (validator.type) {
  1172→      case 'json_schema':
  1173→        try {
  1174→          JSON.parse(output);
  1175→          return { status: 'verified', message: 'Valid JSON' };
  1176→        } catch (e) {
  1177→          return { status: 'failed', message: `Invalid JSON: ${(e as Error).message}` };
  1178→        }
  1179→      
  1180→      case 'code_compiles':
  1181→        // Check if code can be parsed without syntax errors
  1182→        try {
  1183→          new Function(output);
  1184→          return { status: 'verified', message: 'Code compiles' };
  1185→        } catch (e) {
  1186→          return { status: 'failed', message: `Syntax error: ${(e as Error).message}` };
  1187→        }
  1188→
  1189→      case 'url_reachable':
  1190→        try {
  1191→          const res = await fetch(output, { method: 'HEAD' });
  1192→          return res.ok
  1193→            ? { status: 'verified', message: `URL reachable (${res.status})` }
  1194→            : { status: 'failed', message: `URL returned ${res.status}` };
  1195→        } catch (e) {
  1196→          return { status: 'failed', message: `URL unreachable: ${(e as Error).message}` };
  1197→        };
  1198→
  1199→      case 'regex_match':
  1200→        const regex = new RegExp(validator.config.pattern);
  1201→        return regex.test(output)
  1202→          ? { status: 'verified', message: 'Matches pattern' }
  1203→          : { status: 'failed', message: 'Does not match pattern' };
  1204→
  1205→      default:
  1206→        return { status: 'needs_review', message: 'Unknown validator type' };
  1207→    }
  1208→  }
  1209→}
  1210→

  1301→## 7. Phase 3: Governance, Safety & Observability
  1302→
  1303→### 7.1 — Policy & Approval System
  1304→
  1305→**Research basis (agentsNotebooklm.md):** SEAgent's Mandatory Access Control checks every tool call against a Policy Database with 3 outcomes: Block/Deny, User Prompt/Ask, Shadow Mode. AWS and Microsoft mandate least-privilege access, sandboxed execution, and immutable audit logs. Multi-agent systems face confused-deputy attacks and cross-agent privilege escalation.
  1306→
  1307→```typescript
  1308→// NEW FILE: src/lib/agent/policy.ts
  1309→export type RiskLevel = 'low' | 'medium' | 'high' | 'critical';
  1310→export type PolicyAction = 'allow' | 'block' | 'ask_user' | 'shadow';
  1311→
  1312→export interface PolicyRule {
  1313→  id: string;
  1314→  name: string;
  1315→  description: string;
  1316→  condition: PolicyCondition;
  1317→  action: PolicyAction;
  1318→  priority: number;  // Higher = evaluated first
  1319→  enabled: boolean;
  1320→}
  1321→
  1322→export interface PolicyCondition {
  1323→  tools?: string[];        // Which tools this applies to
  1324→  roles?: AgentRole[];     // Which roles
  1325→  riskLevels?: RiskLevel[]; // Which risk levels
  1326→  agents?: string[];       // Specific agent IDs
  1327→}
  1328→
  1329→export interface PolicyCheckResult {
  1330→  allowed: boolean;
  1331→  action: PolicyAction;
  1332→  matchedPolicies: PolicyRule[];
  1333→  requiresApproval: boolean;
  1334→}
  1335→
  1336→export class PolicyEngine {
  1337→  private policies: PolicyRule[] = [];
  1338→
  1339→  constructor() {
  1340→    this.loadDefaultPolicies();
  1341→  }
  1342→
  1343→  async check(
  1344→    tool: string,
  1345→    role: AgentRole,
  1346→    riskLevel: RiskLevel,
  1347→    agentId: string
  1348→  ): Promise<PolicyCheckResult> {
  1349→    const matched: PolicyRule[] = [];
  1350→    let finalAction: PolicyAction = 'allow';  // Default allow
  1351→
  1352→    // Sort by priority (highest first)
  1353→    const sorted = [...this.policies]
  1354→      .filter(p => p.enabled)
  1355→      .sort((a, b) => b.priority - a.priority);
  1356→
  1357→    for (const policy of sorted) {
  1358→      if (this.matchesCondition(policy.condition, tool, role, riskLevel, agentId)) {
  1359→        matched.push(policy);
  1360→        // Most specific (highest priority) wins
  1361→        if (finalAction === 'allow' || policy.priority >= (matched[0]?.priority ?? 0)) {
  1362→          finalAction = policy.action;
  1363→        }
  1364→      }
  1365→    }
  1366→
  1367→    return {
  1368→      allowed: finalAction === 'allow',
  1369→      action: finalAction,
  1370→      matchedPolicies: matched,
  1371→      requiresApproval: finalAction === 'ask_user'
  1372→    };
  1373→  }
  1374→
  1375→  private matchesCondition(
  1376→    condition: PolicyCondition,
  1377→    tool: string,
  1378→    role: AgentRole,
  1379→    riskLevel: RiskLevel,
  1380→    agentId: string
  1381→  ): boolean {
  1382→    if (condition.tools && !condition.tools.includes(tool)) return false;
  1383→    if (condition.roles && !condition.roles.includes(role)) return false;
  1384→    if (condition.riskLevels && !condition.riskLevels.includes(riskLevel)) return false;
  1385→    if (condition.agents && !condition.agents.includes(agentId)) return false;
  1386→    return true;
  1387→  }
  1388→
  1389→  private loadDefaultPolicies(): void {
  1390→    this.policies = [
  1391→      { id: 'p1', name: 'Allow read-only tools', description: 'Search and browse are safe', condition: { tools: ['web_search', 'browse_url'] }, action: 'allow', priority: 10, enabled: true },
  1392→      { id: 'p2', name: 'Require approval for code execution', description: 'Code execution is high risk', condition: { tools: ['execute_code'] }, action: 'ask_user', priority: 20, enabled: true },
  1393→      { id: 'p3', name: 'Require approval for write operations', description: 'Writing files is medium risk', condition: { tools: ['write_file'], riskLevels: ['medium', 'high'] }, action: 'ask_user', priority: 15, enabled: true },
  1394→      { id: 'p4', name: 'Block execution by reviewers', description: 'Reviewers should not execute code', condition: { roles: ['reviewer'], tools: ['execute_code'] }, action: 'block', priority: 30, enabled: true },
  1395→      { id: 'p5', name: 'Allow all for general role', description: 'General agents can do anything (with approval for high risk)', condition: { roles: ['general'] }, action: 'allow', priority: 5, enabled: true },
  1396→    ];
  1397→  }
  1398→}
  1399→```

  1401→### 7.2 — Approval Flow
  1402→
  1403→```typescript
  1404→// Integrated into agent execution loop
  1405→async function executeWithPolicy(
  1406→  agent: AgentConfig,
  1407→  tool: string,
  1408→  input: string,
  1409→  policyEngine: PolicyEngine,
  1410→  emitter: EventEmitter
  1411→): Promise<{ result: string; approved: boolean }> {
  1412→  const riskLevel = toolRegistry.get(tool)?.riskLevel ?? 'medium';
  1413→  const policyResult = await policyEngine.check(tool, agent.role ?? 'general', riskLevel, agent.id);
  1414→
  1415→  // Audit log (always written)
  1416→  await db.auditLog.create({
  1417→    data: {
  1418→      agentId: agent.id,
  1419→      action: 'tool_call',
  1420→      details: JSON.stringify({ tool, input: input.substring(0, 500), riskLevel }),
  1421→      outcome: policyResult.action,
  1422→      riskLevel
  1423→    }
  1424→  });
  1425→
  1426→  if (policyResult.action === 'block') {
  1427→    emitter.emit('policy', { type: 'blocked', tool, reason: 'Policy blocks this action' });
  1428→    return { result: `Action blocked by policy: ${tool}`, approved: false };
  1429→  }
  1430→
  1431→  if (policyResult.action === 'ask_user') {
  1432→    // Create approval request and pause
  1433→    const approval = await db.approvalRequest.create({
  1434→      data: {
  1435→        agentId: agent.id,
  1436→        tool,
  1437→        input: input.substring(0, 1000),
  1438→        riskLevel,
  1439→        status: 'pending'
  1440→      }
  1441→    });
  1442→
  1443→    emitter.emit('policy', { type: 'approval_required', approvalId: approval.id, tool, riskLevel });
  1444→
  1445→    // Wait for approval (polling or WebSocket)
  1446→    const decision = await waitForApproval(approval.id, emitter);
  1447→    
  1448→    if (decision === 'denied') {
  1449→      return { result: `Action denied by user: ${tool}`, approved: false };
  1450→    }
  1451→  }
  1452→
  1453→  if (policyResult.action === 'shadow') {
  1454→    // Execute but only log, don't apply effects
  1455→    emitter.emit('policy', { type: 'shadow_mode', tool });
  1456→  }
  1457→
  1458→  // Execute the tool
  1459→  const result = await toolRegistry.executeWithVerification(tool, input);
  1460→  return { result: result.result, approved: true };
  1461→}

  1577→
  1578→export interface SystemStatus {
  1579→  state: SystemState;
  1580→  activeRuns: number;
  1581→  pendingApprovals: number;
  1582→  systemLoad: number;       // 0-1
  1583→  totalTokensUsed: number;
  1584→  lastActivity: Date;
  1585→  agentsOnline: number;
  1586→}
  1587→
  1588→export class SystemStateManager {
  1589→  private state: SystemState = 'idle';
  1590→  private listeners: Set<(old: SystemState, new_: SystemState) => void> = new Set();
  1591→
  1592→  async transition(newState: SystemState, reason?: string): Promise<void> {
  1593→    const old = this.state;
  1594→    this.state = newState;
  1595→    this.listeners.forEach(fn => fn(old, newState));
  1596→    
  1597→    // Emit SSE event for UI
  1598→    // Persist to DB for recovery after restart
  1599→  }
  1600→
  1601→  getStatus(): SystemStatus {
  1602→    return {
  1603→      state: this.state,
  1604→      activeRuns: 0, // from activeOrchestrations.size
  1605→      pendingApprovals: 0, // from DB count
  1606→      systemLoad: 0, // from process.memoryUsage()
  1607→      totalTokensUsed: 0, // from metrics
  1608→      lastActivity: new Date(),
  1609→      agentsOnline: 0
  1610→    };
  1611→  }
  1612→
  1613→  onStateChange(listener: (old: SystemState, new_: SystemState) => void): () => void {
  1614→    this.listeners.add(listener);
  1615→    return () => this.listeners.delete(listener);
  1616→  }
  1617→}
