    33→01   EXECUTIVE SUMMARY
    34→Hermes is no longer a “workflow engine” project. It is evolving into a deterministic runtime platform, with agent execution as
    35→merely one application layer built on top of a proven kernel. This document defines the phased engineering roadmap from
    36→kernel validation through to distributed multi-node federation.
    37→The roadmap comprises seven phases (Phase 0 through Phase 6), each with explicit objectives, deliverables, execution flows,
    38→and success criteria. The strategic foundation of the entire platform rests on Phase 0: proving that Hermes can deterministically
    39→reconstruct reality from facts. Everything else is built on top of that kernel.
    40→⚠ STRATEGIC PRIORITY
    41→No subsequent phase may begin until Phase 0 success criteria are fully demonstrated. The deterministic kernel is the
    42→non-negotiable foundation of the entire platform.
    43→02   STRATEGIC CONTEXT
    44→The core architectural thesis of Hermes is this: most agent frameworks begin by building agents, then attempt to retrofit
    45→governance, observability, and determinism. Hermes inverts this. The deterministic kernel is built first. Governance is built
    46→second. Agents are introduced only after the substrate beneath them is proven correct and mature.
    47→The strategic inflection point is between Phase 0 and Phase 1. Once the event stream → deterministic replay → identical state
    48→reconstruction chain is validated, the hardest and most differentiated part of the platform is complete. All subsequent phases
    49→add capabilities around a proven kernel, rather than discovering the kernel while simultaneously building agents, UIs,
    50→orchestration, and governance.

   274→1. ABSTRACT
   275→This RFC defines the Hermes Runtime as a deterministic, replayable state machine governed by a strict hierarchy of compiled
   276→intermediate representations, anchored by an executable constitution.
   277→The runtime treats LLMs as proposal generators. All actions are filtered through synchronous policy evaluation, executed as
   278→side-effects, and recorded as causal facts. The kernel reducer derives reality exclusively from state-transition facts
   279→(SystemEvent), which must provably trace their origin to execution attempts (ExecutionEvent).
   280→This RFC formalizes:
   281→An executable ConstitutionIR with strict precedence and severity.
   282→Causal closure between execution attempts and state transitions.
   283→A primitive, explicitly typed state-transition taxonomy.
   284→An event-sourced blackboard projection model.
   285→Cryptographic authorship via signatures.
   286→The TraceManifest as the genesis block of execution.
   287→2. GOALS
   288→The Hermes Runtime exists to support workflows that are:
   289→Deterministic under replay with bounded recovery
   290→Causally closed (no orphaned state mutations)
   291→Constitutionally supreme and policy-governed
   292→Auditable with full provenance and cryptographic authorship
   293→Robust to probabilistic model output, retries, and partial failure

   307→3. TERMINOLOGY
   308→TERM
   309→DEFINITION
   310→ConstitutionIR
   311→The runtime-wide axiomatic law. Compiled into executable validators. Overrides all other IRs.
   312→TraceManifest
   313→The genesis block of a trace. Binds a traceId to its specific Constitution, Plan, and Policy hashes.
   314→Causal Closure
   315→The invariant that every state-mutating SystemEvent must reference the ExecutionEvent or DecisionEvent
   316→that caused it, eliminating trust in rootless state transitions.
   317→Event-Sourced
   318→Blackboard
   319→A memory substrate where state is a projection of BLACKBOARD_WRITTEN system events, rather than
   320→an opaque mutated object.
   321→Signature
   322→A cryptographic attestation of authorship, binding an identity to an artifact or event.
   323→4. ARCHITECTURAL INVARIANTS
   324→4.1 Factual Reduction: The reducer consumes only SystemEvents. No other event tier may directly mutate kernel state.
   325→4.2 Causal Closure: Every SystemEvent representing a step or workflow transition must reference the executionEventId or
   326→decisionEventId that precipitated it. Rootless state transitions are constitutionally invalid.
   327→4.3 Constitutional Supremacy: IR precedence is strictly enforced. Conflict at any level results in an immediate
   328→FATAL_CONSTITUTIONAL_VIOLATION.
   329→ConstitutionIR > PolicyIR > ExecIR > HermesIR
   330→4.4 Single Authoritative Sequencer (Model A): To guarantee strict deterministic replay, the runtime operates on a single-
   331→authoritative-event-sequencer model. eventSequence and logicalClock are sufficient. Vector clocks are excluded from the
   332→kernel; distributed execution is achieved by delegating to isolated sub-traces or external workers whose results are normalized
   333→back into the authoritative sequence.
   334→4.5 Event-Sourced Memory: Blackboard state is derived by folding BLACKBOARD_WRITTEN events. In-place mutation
   335→outside the event stream is prohibited.
   336→4.6 Authorship over Integrity: Hashes prove integrity; signatures prove authority. Governance proposals, approvals, and
   337→constitutional amendments require cryptographic signatures.
   338→5. CANONICAL IR MODEL & PRECEDENCE
   339→5.1 ConstitutionIR
   340→Defines runtime-wide executable axioms. The ConstitutionIR is the supreme governing artifact of a trace. All validators
   341→compiled from it run synchronously prior to any policy or execution evaluation.
   342→interface ConstitutionIR {
   343→  id: string;
   344→  version: string;
   345→  constitutionalHash: string;
   346→  axioms: ConstitutionalAxiom[];
   347→}
   348→interface ConstitutionalAxiom {
   349→  id: string;
   350→  description: string;
   351→  severity: 'FATAL' | 'ERROR' | 'WARNING';
   352→  validator: string; // URI or hash of a deterministic validation function
   353→}
   354→
   355→--- Page 8 ---
   356→Example Axiom (Severity: FATAL): "No STEP_SUCCEEDED event is valid without a preceding ExecutionEvent referencing the
   357→same stepId."
   358→5.2 HermesIR (Intent), ExecIR (Mechanics), PolicyIR (Law)
   359→As defined in v1.3, but strictly subordinate to ConstitutionIR. These IRs govern intent expression, execution mechanics, and
   360→runtime law respectively. No construct within these IRs may supersede or conflict with a constitutional axiom. Violations are
   361→surfaced as FATAL_CONSTITUTIONAL_VIOLATION kernel halts per Invariant 4.3.
   362→6. TRACEMANIFEST (GENESIS BLOCK)
   363→Before execution begins, a trace must be instantiated with its constitutional and operational anchors. The TraceManifest is the
   364→first artifact written and is immutable for the lifetime of the trace.
   365→interface TraceManifest {
   366→  traceId: string;
   367→  planId: string;
   368→  constitutionHash: string;
   369→  executionPlanHash: string;
   370→  policyHash: string;
   371→  initiatedBy: Signature;
   372→  createdAt: number;
   373→}
   374→Replay validation begins by loading the TraceManifest to verify that subsequent events adhere to the correct constitution and
   375→plans. Any mismatch between the manifest hashes and the artifacts available at replay time constitutes a fatal integrity
   376→violation.
   377→7. KERNEL STATE & EVENT-SOURCED BLACKBOARD
   378→7.1 KernelState
   379→The canonical kernel state is the complete projection of all SystemEvents consumed by the reducer since the genesis block.
   380→interface KernelState {
   381→  workflowStatus: 'INITIALIZED' | 'RUNNING' | 'BLOCKED' | 'COMPLETED' | 'FAILED';
   382→  stepStatuses: Record<string, 'PENDING' | 'RUNNING' | 'COMPLETED' | 'FAILED'>;
   383→  blackboard: KernelBlackboard; // Projection of BLACKBOARD_WRITTEN events
   384→  eventSequence: number;
   385→}
   386→7.2 Blackboard as Projection
   387→The KernelBlackboard is no longer mutated directly. It is the left-fold of BLACKBOARD_WRITTEN events. Every slot write
   388→carries provenance metadata and a version counter to enable conflict detection and auditing.

   393→  value: unknown;

   402→8. EVENT TAXONOMY & CAUSAL LINKING
   403→Events are strictly tiered. Only SystemEvents are valid reducer inputs. SystemAction values are an explicit, closed set of
   404→primitives — no generic details blobs are permitted at the type level.
   405→8.1 Base Event
   406→All events in the Hermes Runtime extend BaseEvent. The cryptographic chain linkage (eventHash / previousEventHash)
   407→enables tamper detection across the full trace.
   408→interface BaseEvent {
   409→  eventId: string;
   410→  traceId: string;
   411→  eventSequence: number;
   412→  causationId: string | null;
   413→  correlationId: string;
   414→  tier: EventTier;
   415→  timestamp: number;
   416→  logicalClock: number;
   417→  eventHash: string;
   418→  previousEventHash: string | null;
   419→  signatures?: Signature[]; // Required for governance/approval events
   420→}
   421→8.2 SystemEvent (The Only Reducer Input)
   422→State transitions are primitive and explicit. No generic details blobs at the type boundary. Each SystemAction has a strictly
   423→typed payload schema in the implementation layer.
   424→type SystemAction =
   425→  | 'WORKFLOW_INITIALIZED' | 'WORKFLOW_BLOCKED' | 'WORKFLOW_FAILED' | 'WORKFLOW_COMPLETED'
   426→  | 'STEP_STARTED' | 'STEP_SUCCEEDED' | 'STEP_FAILED'
   427→  | 'BLACKBOARD_WRITTEN' | 'BLACKBOARD_CLEARED'
   428→  | 'POLICY_VIOLATION' | 'CHECKPOINT_REACHED';
   429→interface SystemEvent extends BaseEvent {
   430→  tier: 'SYSTEM';
   431→  payload: {
   432→    action: SystemAction;
   433→    // Causal closure: The event that authorized this state mutation
   434→    executionEventId?: string; // Required for STEP_SUCCEEDED/FAILED
   435→    decisionEventId?: string;  // Required for STEP_STARTED
   436→    details?: Record<string, unknown>; // Strictly typed per action in implementation
   437→  };
   438→}
   439→

   441→8.3 ExecutionEvent
   442→Records the factual result of a side-effect boundary. An ExecutionEvent is the ground truth of what occurred at a tool
   443→invocation. It is the mandatory antecedent of any STEP_SUCCEEDED or STEP_FAILED system event.
   444→interface ExecutionEvent extends BaseEvent {
   445→  tier: 'EXECUTION';
   446→  payload: {
   447→    toolId: string;
   448→    invocationId: string;
   449→    inputs: unknown;
   450→    outputs: unknown;
   451→    status: 'SUCCESS' | 'FAILURE';
   452→  };
   453→}
   454→9. SIGNATURE MODEL
   455→Integrity (hashes) prevents tampering. Signatures establish authority. These are orthogonal concerns: a valid hash on a
   456→fraudulent artifact is meaningless without a corresponding valid signature from an authorized identity.
   457→interface Signature {
   458→  signerId: string;
   459→  algorithm: string;
   460→  value: string; // Cryptographic signature over the artifact hash
   461→  timestamp: number;
   462→}
   463→Signature requirements:
   464→GovernanceProposal must be signed by the proposing Council Agent.
   465→REQUIRE_APPROVAL outcomes must be resolved via a signed DecisionEvent from an authorized human or system.
   466→ConstitutionIR amendments require quorum signatures.
   467→10. POLICY & CONSTITUTIONAL EVALUATION
   468→10.1 Precedence Evaluation Flow
   469→When a DecisionEvent occurs, the following evaluation sequence is strictly enforced in order:
   470→Constitutional Check: Does the decision violate a ConstitutionIR axiom? 
   471→Yes (FATAL): Halt kernel. Emit FATAL_CONSTITUTIONAL_VIOLATION.
   472→Yes (ERROR/WARNING): Emit violation event, proceed or block based on severity logic.
   473→Policy Check: Does PolicyIR permit the execution? 
   474→DENY: Emit POLICY_VIOLATION, transition step to FAILED.
   475→REQUIRE_APPROVAL: Pause until signed approval DecisionEvent arrives.
   476→ALLOW / CONSTRAINED_ALLOW: Proceed to ExecutionBoundary.
   477→PURITY INVARIANT
   478→Both Constitution and Policy evaluation must remain pure, deterministic, network-isolated, and side-effect free. Any
   479→evaluator that performs I/O, network access, or non-deterministic computation is constitutionally invalid and must be
   480→rejected at load time.

   493→11. EXECUTION BOUNDARY & CAUSAL CLOSURE
   494→The execution boundary guarantees that state transitions only occur as a verified, recorded consequence of side-effects. No
   495→state may change without a provable causal antecedent in the event stream.
   496→CLOSURE ENFORCEMENT RULE
   497→If a SystemEvent with action STEP_SUCCEEDED or STEP_FAILED is fed into the reducer, and its executionEventId
   498→does not point to a valid ExecutionEvent in the trace, the reducer must reject the event and throw a
   499→FATAL_CONSTITUTIONAL_VIOLATION. There is no recovery path from a rootless state transition.
   500→12. REPLAY CONTRACT
   501→Replay reconstructs the runtime deterministically from the TraceManifest and the factual event stream. A replay that does not
   502→produce the recorded terminal state is evidence of either implementation divergence or event stream corruption — both of
   503→which are fatal.
   504→12.1 Replay Steps
   505→Load TraceManifest — Verify genesis hashes against available artifacts.
   506→Initialize state from Checkpoint — If applicable; otherwise initialize from scratch.
   507→Consume events strictly by eventSequence — No out-of-order processing permitted.
   508→Filter for SystemEvent tier only — All other tiers are ignored by the reducer.
   509→Validate Causal Closure — Ensure STEP_SUCCEEDED / STEP_FAILED events reference valid ExecutionEvents within
   510→the trace.
   511→Feed into reducer — Apply each SystemEvent to produce the next KernelState.
   512→Validate cryptographic chain linkage — Verify eventHash / previousEventHash integrity across the full sequence.
   513→Assert deep equality — Compare computed terminal state against recorded terminal state. Any divergence is a fatal
   514→replay violation.
   515→13. FINAL STATEMENT
   516→"Hermes is a fact-derived reality engine."
   517→Models propose. Policies judge. Executions occur. Facts are recorded. Reducers derive reality.
   518→By enforcing causal closure, executable constitutions, explicit primitive transitions, and event-sourced memory, the system
   519→eliminates the ambiguity that allows probabilistic components to corrupt deterministic state. The runtime does not guess what
   520→happened; it cryptographically proves what occurred, strictly ordered, and derives the present from that proof.

   551→1. ABSTRACT
   552→This RFC defines the exact mechanical representation of truth in the Hermes Runtime. If RFC-001 is the constitutional law,
   553→RFC-002 is the criminal code — it specifies the precise schemas, serialization rules, cryptographic algorithms, and validation
   554→procedures required to ensure that a recorded trace can be replayed to produce byte-identical state reconstruction.
   555→2. SERIALIZATION AND CANONICALIZATION
   556→To guarantee deterministic replay across different languages, runtimes, and timestamps, events must be canonicalized before
   557→hashing or signing.
   558→2.1 Format: All events are serialized as JSON strings.
   559→2.2 Canonicalization Algorithm: We adopt RFC 8785 (JSON Canonicalization Scheme — JCS). JCS ensures that JSON
   560→payloads with identical logical content produce identical byte representations by strictly defining whitespace, string
   561→escaping, and property ordering.
   562→2.3 Numeric Constraints: To prevent floating-point drift across runtimes: 
   563→All timestamps MUST be represented as 64-bit integers (Unix epoch milliseconds).
   564→No floating-point numbers are permitted in canonicalized payloads. Decimals (e.g., costs, confidence scores) MUST
   565→be represented as strings (e.g., "0.95") or scaled integers.
   566→3. CRYPTOGRAPHIC HASHING AND CHAINING
   567→The audit chain guarantees the temporal integrity and tamper-evidence of a trace.
   568→3.1 Hashing Algorithm: SHA-256.
   569→3.2 Chain Construction: Every event is linked to its predecessor within the same traceId. The construction procedure is as
   570→follows:
   571→Construct the event object, leaving eventHash and previousEventHash as empty strings ("").
   572→Replace previousEventHash with the eventHash of the preceding event in the trace. For the first event in the trace,
   573→use the hash of the TraceManifest.
   574→Canonicalize the object using JCS, excluding the still-empty eventHash field.
   575→Compute the SHA-256 hash of the canonicalized UTF-8 string.

   781→function validateTrace(manifest: TraceManifest, events: BaseEvent[]): boolean {
   782→  let prevHash = hashManifest(manifest);
   783→  let expectedSequence = 1;
   784→  for (const event of events) {
   785→    // 1. Sequence Check
   786→    if (event.eventSequence !== expectedSequence) throw new Error("Sequence gap");
   787→    // 2. Chain Integrity
   788→    if (event.previousEventHash !== prevHash) throw new Error("Chain broken");
   789→    // 3. Hash Verification
   790→    const computedHash = computeEventHash(event);
   791→    if (computedHash !== event.eventHash) throw new Error("Tampered event");
   792→    // 4. Causal Closure (Constitutional Axiom)
   793→    if (event.tier === 'SYSTEM') {
   794→      const sysEvent = event as SystemEvent;
   795→      if (sysEvent.payload.action === 'STEP_SUCCEEDED' || sysEvent.payload.action === 'STEP_FAILED') 
   796→{
   797→        if (!sysEvent.payload.executionEventId) {
   798→            throw new Error("Causal closure violation: rootless state transition");
   799→        }
   800→        // Verify the referenced ExecutionEvent exists in the past events
   801→        if (!events.find(e => e.eventId === sysEvent.payload.executionEventId)) {
   802→            throw new Error("Phantom execution reference");
   803→        }
   804→      }
   805→    }
   806→    prevHash = computedHash;
   807→    expectedSequence++;
   808→  }
   809→  return true;
   810→}
